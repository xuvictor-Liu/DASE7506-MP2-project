# Third research round: target not achieved

The requested target is at least 90% official full-test accuracy. This research round did **not** achieve it and did not produce a model that improves on V2's validation selection accuracy. The designated submission remains the unchanged V2 model: official test **394/467 = 84.36830835117773%**. At least 421/467 would be needed to reach 90%, a gap of 27 questions. No additional test scoring was performed in round three.

## Protocol

Seven new learned verifier/calibration families and one arithmetic-template classifier were investigated. Hyperparameters for the new verifier families were selected using a fixed training-only question holdout: of 2,114 training questions with at least two distinct valid parsed answers, 423 were held out using seed 731. Easy training questions were additionally used by the multitask and template approaches. Final selected models were retrained using training data and then evaluated on the official validation bank. Each model family has its full selection log in its `runs_*` directory. The final complementarity comparison uses validation only. The V2 aggregate test score was known from round two; test references and per-example test errors were not inspected for this research.

The training holdout was reused across families and hence is a development set, not an unbiased final estimate. The official hard-validation subset has also been reused across rounds. These limitations argue against interpreting small development fluctuations as reliable gains.

## Results

| Method | Training hard holdout | Official hard validation |
|---|---:|---:|
| Frozen V2 baseline | Not comparable: trained on all training data | **86.48%** |
| Answer-equivalence group pooling, three-seed MLP | 82.27% | 85.92% |
| Direct nonlinear candidate-pair comparator | 82.27% | 85.07% |
| Easy-question correctness + hard-question ranking | 82.74% | 83.66% |
| RBF SVM on projected embeddings and structure | 81.80% | 83.10% |
| Numerical-relation features + YetiRank | 81.80% | 80.85% |
| Question-context/candidate-difference cross features | 76.36% | 79.44% |
| Strict-arithmetic calibration using training OOF scores | 81.32% | 86.48%, identical selected answers to V2 |

The training-holdout column reflects the selected single-fit configuration, while the group/pair/multitask final models average three seeds. It is therefore not a perfectly controlled split-to-split comparison. Projection/statistics for holdout fits are learned on the relevant training portion; final models refit those statistics on training inputs only.

For each new verifier, fixed 25% and 50% score blends with V2 were evaluated after within-question score normalization. None improved over V2. The arithmetic template classifier recovered executable formula templates from 3,521 training reference solutions. The top 96 reusable templates covered only 613 final-fit questions; its predictions covered 192 hard validation questions with only 38.54% accuracy on those covered questions. This is a conditional coverage diagnostic, not an overall selection accuracy, and the approach was rejected.

## Useful finding: arithmetic-parser false positives

The previous numeric substring checker could interpret `x + 108 = 160` as `108 = 160`, or treat a fragment after the word `of` as a standalone left-hand expression. The new experimental `strict_arithmetic.py` uses boundary guards to reject incomplete expressions while still checking later fully numeric links in an equality chain. Unit checks cover the variable-boundary case, percentage wording, an incorrect fraction equality, and a wrong explicit sum.

On training valid candidates, the old checker flagged 14.09% of incorrect candidates and 9.75% of correct candidates. The strict checker flags 5.30% and 1.58%, respectively. It is more selective but covers fewer errors. Final-answer correctness and intermediate consistency remain distinct; a flag is not itself proof that the final answer is wrong. Fitting its calibration on training out-of-fold neural scores leaves the validation choices unchanged. Consequently, this research code has not been substituted into the frozen V2 inference dependency chain; V2's saved hashes still match.

## Reproduce research

Use the existing Python 3.12 environment and `code/requirements-method.txt`. From `code/`, run:

```text
python train_group.py
python train_numeric.py
python train_interaction.py
python train_multitask.py
python train_pair.py
python train_strict.py
python train_programs.py
python train_kernel.py
python compare_round3.py
```

`train_strict.py` requires the training-fold checkpoints generated by round two's `train_stack.py`. `compare_round3.py` also requires the preserved V2 final bundle and all new verifier artifacts. The numeric ranker uses CatBoost; the kernel model is exported to float32 arrays with a NumPy inference implementation. All runs are CPU based, with four numerical-library threads per training process. Some independent jobs overlapped; the per-script elapsed times are recorded and should not be summed as wall-clock duration. No external datasets, pretrained weights, or LLM evaluation calls were used.

`code/runs_round3/comparison.json` is the complete official-validation comparison. `code/runs_round3/selection.json` records that the V2 baseline was retained and no test was scored. The bootstrap interval for the selected unchanged baseline versus itself is mechanically [0,0] and must not be interpreted as statistical evidence about generalization.
